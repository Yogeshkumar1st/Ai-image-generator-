## 2026-03-24 - [DOM XSS via localStorage]
**Vulnerability:** The application was vulnerable to DOM-based XSS when rendering user history from `localStorage`. The `loadHistory` function used `innerHTML` to interpolate the `item.url` property into an `<img src="...">` tag and its `onclick` handler. Because `encodeURIComponent` does not encode single quotes (`'`), an attacker could break out of the `onclick='...'` attribute context by including a single quote in their prompt, which ends up in the `url`, executing arbitrary JavaScript when the gallery is loaded.
**Learning:** `encodeURIComponent` does not make data safe for injection into single-quoted HTML attributes. Also, data loaded from `localStorage` should be treated as untrusted, especially if it originated from user input (like the prompt). Interpolating untrusted data via `innerHTML` is inherently risky.
**Prevention:** Always use safe DOM APIs (like `document.createElement`, `element.src = ...`, `element.onclick = ...`, or `element.textContent = ...`) instead of `innerHTML` when rendering data that originates from user input or external sources, even if it comes from `localStorage`.
