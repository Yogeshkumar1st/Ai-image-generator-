## 2025-02-14 - Fix DOM-based XSS in loadHistory
**Vulnerability:** The application is vulnerable to DOM-based Cross-Site Scripting (XSS) in `loadHistory()` inside `index.html`. It takes the `url` from `localStorage` (`xhistory` key) and directly interpolates it into an `innerHTML` string (`<img src="${item.url}" onclick="viewImage('${item.url}')">`). The problem is that the `url` is originally generated using `encodeURIComponent(prompt)`, which **does not escape single quotes (`'`)**. An attacker who enters a prompt containing a single quote can break out of the `onclick` handler's attribute string and inject arbitrary JavaScript (e.g., `x');alert(1);//`). Even though `localStorage` is isolated to the origin, this is still a vulnerability if a malicious URL is shared or history is poisoned.
**Learning:** `encodeURIComponent()` does not escape single quotes, making it unsafe to trust its output directly within single-quoted HTML attributes when using `innerHTML`. Using `innerHTML` with unsanitized data from `localStorage` is dangerous.
**Prevention:** When refactoring for security to prevent DOM-based XSS, prefer using safe DOM manipulation APIs (e.g., `document.createElement`, `img.src = ...`, `img.onclick = () => viewImage(...)`) over `innerHTML` assignments. Avoid injecting variables into raw HTML strings.
