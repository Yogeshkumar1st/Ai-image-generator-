## 2024-05-18 - DOM-based XSS in Gallery History
**Vulnerability:** The application was vulnerable to DOM-based Cross-Site Scripting (XSS) because user input (the image URL containing the prompt) from `localStorage` was concatenated directly into an HTML string using template literals and assigned to `div.innerHTML`. The `encodeURIComponent` function used earlier on the prompt did not escape single quotes, allowing an attacker to break out of the single-quoted `onclick` attribute and inject arbitrary JavaScript.
**Learning:** Even when inputs are encoded using `encodeURIComponent`, they can still be dangerous if placed within single-quoted HTML attributes because `encodeURIComponent` does not escape single quotes. Furthermore, using `innerHTML` with unsanitized data from `localStorage` is a classic vector for DOM-based XSS.
**Prevention:** Avoid using `innerHTML` for dynamic content creation. Instead, use safe DOM manipulation APIs like `document.createElement`, direct property assignments (e.g., `img.src = item.url`), and attach event listeners programmatically (e.g., `img.onclick = () => viewImage(item.url)`).
