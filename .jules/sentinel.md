## 2023-10-27 - DOM-based XSS via innerHTML in Image Gallery
**Vulnerability:** The application was vulnerable to DOM-based Cross-Site Scripting (XSS) in the `loadHistory` function. User input (the generated image URL containing the prompt) was stored in `localStorage` and then later rendered into the DOM using `div.innerHTML = \`<img src="${item.url}" onclick="viewImage('${item.url}')">\`;`. While the initial prompt was encoded with `encodeURIComponent()`, this encoding does not escape single quotes (`'`). This allowed an attacker to inject a payload like `a'-alert(1)-'` which would break out of the single-quoted `onclick` attribute and execute arbitrary JavaScript when the gallery item was rendered.
**Learning:** Using `innerHTML` with any user-controlled data, even if it has passed through basic encoding functions like `encodeURIComponent`, is highly risky. In HTML contexts (especially within attributes), it's very easy to break out of quotes and inject malicious event handlers.
**Prevention:** Always use safe DOM manipulation APIs like `document.createElement`, setting properties directly (e.g., `img.src`, `img.onclick`), and `appendChild`. This ensures that the browser treats the input strictly as data, not as executable code.
