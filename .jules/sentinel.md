## 2024-05-15 - [CRITICAL] Stored DOM XSS via innerHTML and localStorage
**Vulnerability:** Found a Stored DOM XSS vulnerability in `index.html` within the `loadHistory()` function. The application read user-controlled data (`url` and `prompt`) from `localStorage` under the key `xhistory` and rendered it directly into the DOM using `element.innerHTML = \`<img src="${item.url}" ...>\``. This allowed execution of arbitrary JavaScript if malicious data was stored in `localStorage`.
**Learning:** Using `innerHTML` with unsanitized data from `localStorage` (or any other untrusted source) is a critical security risk leading to Stored DOM XSS. Data in `localStorage` can persist and affect the user across sessions, making this particularly dangerous. Even if data is assumed to be safe (e.g., generated by the app), it must be treated as untrusted because `localStorage` can be modified by other scripts on the same origin or via developer tools.
**Prevention:** Never use `innerHTML` when rendering data from `localStorage` or other untrusted sources. Always use safe DOM API methods such as `document.createElement()`, `element.textContent`, and `element.setAttribute()` to construct and modify the DOM. This ensures that the browser treats the data as text or specific attribute values, preventing the execution of injected scripts.
