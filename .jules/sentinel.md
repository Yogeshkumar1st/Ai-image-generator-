## 2026-03-31 - [High] Fix XSS Vulnerability in History Display
**Vulnerability:** The application stored user prompts in `localStorage` and displayed them directly into the DOM without sanitization, leading to a Cross-Site Scripting (XSS) vulnerability. `encodeURIComponent` was used when creating the API URL, but the unencoded `prompt` was stored and could potentially be rendered later if the application was expanded. However, a more immediate XSS vector exists in the `viewImage` implementation or if malicious URLs are stored and injected via `innerHTML` in `loadHistory()`. Actually looking at `loadHistory()`: `div.innerHTML = \`<img src="${item.url}" onclick="viewImage('${item.url}')">\`;`. If `item.url` contains a single quote, it breaks the `onclick` handler and allows injecting arbitrary HTML/JS. `encodeURIComponent` does *not* encode single quotes (`'`).
**Learning:** `encodeURIComponent` does not escape single quotes, which is a common oversight leading to XSS when values are interpolated into single-quoted HTML attributes. Also, using `innerHTML` with any user-influenced data (even partially) is risky.
**Prevention:** Use DOM APIs (e.g., `document.createElement`, `element.setAttribute`, `element.appendChild`) instead of `innerHTML` for rendering user-generated content or URLs that might contain unescaped characters.
