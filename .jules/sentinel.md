## 2024-04-26 - [DOM-based XSS via innerHTML]
**Vulnerability:** A Cross-Site Scripting (XSS) vulnerability was found in `index.html` where user-controlled URLs from `localStorage` were being directly injected into the DOM using `innerHTML` (`div.innerHTML = \`<img src="${item.url}" onclick="viewImage('${item.url}')">\``). Since `encodeURIComponent` does not encode single quotes (`'`), an attacker could craft a prompt or manipulate `localStorage` to inject arbitrary JavaScript via the `onclick` handler or escape the `src` attribute.
**Learning:** Even if data originates from an external API or seemingly benign user interaction (like image generation prompts), storing it in `localStorage` and later rendering it without sanitization or via unsafe DOM methods (`innerHTML`) creates a persistent XSS vector. The lack of single-quote encoding in `encodeURIComponent` makes attribute interpolation particularly risky.
**Prevention:** Always use safe DOM API methods (e.g., `document.createElement`, setting properties like `.src`, `.onclick`, or `textContent`) when rendering dynamic content, rather than interpolating strings into `innerHTML`. Treat data from `localStorage` as untrusted.
