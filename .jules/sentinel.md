## 2024-07-05 - Refactored DOM generation to prevent Cross-Site Scripting (XSS)
**Vulnerability:** A DOM-based Cross-Site Scripting (XSS) vulnerability was found in the application's gallery rendering logic (`loadHistory()` in `index.html`). The application previously used `innerHTML` with string interpolation (`div.innerHTML = \`<img src="\${item.url}" ...>\``) to dynamically construct HTML elements from user-supplied image URLs loaded from `localStorage`. Because `item.url` was not properly escaped (specifically single quotes), an attacker could craft a malicious URL containing unescaped HTML attributes to execute arbitrary JavaScript (e.g., `https://example.com/img.jpg' onclick='alert("XSS")' class='`).
**Learning:** Using `innerHTML` with dynamic, unescaped user input, even when partially processed by functions like `encodeURIComponent` elsewhere, creates severe XSS vulnerabilities when constructing HTML elements. Native JavaScript methods like `document.createElement` are fundamentally safer because they handle the sanitization and element construction directly, bypassing string parsing entirely.
**Prevention:** Always construct DOM elements dynamically using safe native APIs (e.g., `document.createElement`, `element.src = value`, `element.onclick = fn`) instead of relying on string concatenation or interpolation with `innerHTML`.
